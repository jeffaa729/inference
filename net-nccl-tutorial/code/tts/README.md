# 把面试题库变成有声书（`code/tts/`）

把 `docs/interview.md` 的 270 道题读成音频，生成 **MP3 + 播客订阅源**，这样通勤 / 走路 / 健身房都能听。

```
270 题 → 可朗读 254 题 · 约 3.3 小时音频 · 每章 5–40 分钟
两种产物：MP3 + 播客订阅（听）　/　MP4 带逐句字幕（边看边听）
```

---

## 朗读格式

**只有两段**，没有别的层级：

```
第 136 题。集合通信有哪些操作？
答案：八个：broadcast、reduce、all-reduce、scatter、gather、all-gather、
reduce-scatter、all-to-all（另有 scan 等）
关键恒等式：all-reduce = reduce-scatter + all-gather
…
```

- `第 N 题。` + 题干 —— 听的时候能立刻知道到第几题了
- `答案：` 之后的正文**连续读完**，不再分「答/数字/坑」三层标签
  （但正文里自带的「常见错答：」「关键数字：」会保留 —— 它们是句子的一部分，不是标题）
- **表格转口语**：`策略：TP（张量并行）；切什么：层内的权重矩阵；…`
- **代码块整段丢弃**

## 哪些题不生成

按「**能不能听懂**」自动过滤，默认跳过 **16 题**：

| 判据 | 命中 |
|---|---|
| **§7 手撕代码题**（正文中文只剩 7–27 字） | Q176–Q190（15 题） |
| **中文少于 25 字**（答案是纯公式 / 纯命令） | Q70（Roofline 公式） |

```
可朗读 254 题，预估 195.7 分钟音频
跳过 16 题（代码 / 念不出来）：
  Q70   中文只有 19 字              写出 Roofline 模型与判据
  Q176  中文只有 19 字              向量加法 c = a + b
  …
```

阈值都可调，看着不对就改：

```powershell
build_audiobook.py --check                  # 先看跳过哪些
build_audiobook.py --include 70,176         # 强制加回某几题
build_audiobook.py --exclude 201,202        # 强制排除
build_audiobook.py --no-skip-code           # 连 §7 也念
build_audiobook.py --min-cjk 40             # 更严格
```

> **注意**：`--min-cjk` 调高会误伤「集合通信有哪些操作」（中文 37 字，但内容全是可朗读的英文术语）。
> 默认值 25 是试出来的平衡点。

## 为什么是 MP3 而不是 MP4

| 格式 | 判断 | 理由 |
|---|---|---|
| **MP4** | ❌ 不推荐 | 你要的是**音频**。MP4 得拖一条静态图轨，体积翻倍，而且手机播放器普遍不支持「记忆播放位置 + 变速 + 单集下载」 |
| **MP3（每题一个）** | ✅ 打底 | 通用、可拖动、体积小。**270 个文件才能跳着听** —— 一个 3 小时的整块 MP3 在手机上没法用 |
| **M4B（带章节）** | ✅ 可选 | 有声书标准格式，Apple Books / VLC 支持章节跳转；安卓支持参差 |
| **播客 RSS** | ⭐ **最推荐** | 生成 `feed.xml`，用**小宇宙 / Apple Podcasts / Pocket Casts / AntennaPod** 订阅 → **自动记忆进度、倍速、批量下载、按集排序**，全部免费，且不用拷文件 |

**所以默认产出 MP3，加 `--feed` 得到播客源。** 想上传视频站再考虑 `--m4b`。

## 快速开始

```powershell
cd code\tts

# 0) 装引擎（已装好，这一步只在换机器时需要）
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install edge-tts

# 1) 只统计，不生成
.\.venv\Scripts\python.exe build_audiobook.py --check

# 2) 试听样音（6 个，约 6 分钟）
.\.venv\Scripts\python.exe make_samples.py
#    -> audio\samples\  里比较 yunjian / xiaoxiao / yunxi / yunyang 四个音色

# 3) 全量生成（约 3.3 小时音频，实际跑 15–30 分钟）
.\.venv\Scripts\python.exe build_audiobook.py --all --voice yunjian

# 4) 按章合并 + 生成有声书 / 播客
.\.venv\Scripts\python.exe build_audiobook.py --all --merge --m4b --feed

# 5) 手机同 Wi-Fi 订阅（起本地服务，用播客 App 填这个地址）
.\.venv\Scripts\python.exe build_audiobook.py --feed --serve
```

**断点续传**：已生成的题会自动跳过，中断了直接重跑同一条命令。

## 最难的部分不是 TTS，是「把 markdown 念成人话」

`interview_parser.py` 负责这一层，它决定了音频能不能听：

| 问题 | 处理 |
|---|---|
| **代码块**（§7 有 3900 行 CUDA） | **整段丢弃**。念 CUDA 代码毫无意义；§7 只念「题面 + 考点 + 源码文件名」 |
| **表格** | 转成口语：`策略：TP；切什么：层内权重矩阵；解决什么：单层放不下…` |
| **`答·` / `数字·` / `坑·`** | `答·` 由 `答案：` 统一承担（避免念两遍）；`数字·`/`坑·` 作为句子前缀保留。**若正文自带小标题则不再叠加**（否则会念成「关键数字：关键恒等式：」） |
| **跨行加粗 `**`** | 整段 `**…**` 跨行时正则匹配不到，会留下孤立的 `**` 被念出来 —— 已加全局清理 |
| **图源 / 源码 / 参考链接** | 丢弃（念 `CC BY-SA 4.0` 只会打断思路） |
| **`→ ⇒ ≈ ≤ ×`** | 转成 `，` `，所以` `约等于` `小于等于` `乘` |
| **`!= == ^2`** | 转成 `不等于` `等于` `的平方` |
| **`Q132` `§5.2`** | 念成 `问题 132` `第 5.2 节` |
| **英文缩写**（TP / KV / NCCL / MoE…） | 逐字母念，否则中文 TTS 会读错 |
| **章节标题** | **重置当前题目** —— 不然最后一题会把下一章的速查表整段吞掉（这个 bug 实际发生过：Q262 曾吞掉整个 §12，生成出 25 分钟的音频） |

改完解析规则后先看文本再合成，比事后听音频快得多：

```powershell
python interview_parser.py --dump Q132     # 看这题会怎么念
python interview_parser.py --stats         # 总时长与每章分布
```

## 换别的 TTS 引擎

`--engine` 支持四种，接口一样：

| 引擎 | 需要什么 | 质量 / 成本 |
|---|---|---|
| **`edge`**（默认） | 什么都不用 | 免费。微软 Edge 朗读的神经网络语音，中文接近商用 |
| `openai` | `OPENAI_API_KEY` | 更好听、可控制语气。3.3 小时音频约 $3–6 |
| `azure` | `AZURE_SPEECH_KEY` + `AZURE_SPEECH_REGION` | 和 edge 同源但更稳、可调 SSML。约 $10–16 |
| `sapi` | 系统装中文语音 | **离线兜底**。Windows 默认只有英文语音，需要另装 |

> **关于 `edge` 的说明**：它走的是 Edge 浏览器的「朗读」接口，属于**非官方用法**、也没有 SLA。
> 个人学习用途是社区通行做法，但**如果要做对外发布的产品，请换成 `openai` / `azure`**。

## 视频版：「边看文字边听」（`build_video.py`）

纯音频适合通勤；**视频版适合想同时看文字的场景**（地铁上、睡前、挂着当学习视频）。

### 版式（v2）

```
┌────────────────────────────────────────────────────────┐
│ Q132 · §5 分布式与通信                       3 / 8     │ ← 页眉 / 页码
│                                                        │
│ 第 132 题 TP、PP、DP、EP 分别解决什么问题？             │  37px
│                                                        │ ← 题目后空一行
│ 答案：策略：TP（张量并行）；                            │ ← 整段正文
│ 切什么：层内的权重矩阵（按列/行切）；                    │   **按 `；` 断行**
│ 解决什么：单层放不下一张卡；                            │   一个字段一行
│ 代价：每层两次 all-reduce，通信最频繁。                  │
│ 策略：PP（流水并行）；                                  │
│ 切什么：按层切；                                        │
│                                                        │
│ ████████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ │ ← 进度条
└────────────────────────────────────────────────────────┘
```

**v1 → v2 改了什么**（都是按反馈改的）：

| v1（弃用） | v2 |
|---|---|
| 逐句高亮，一句一行 | **一屏一整段**，按宽度自动换行；能停下来读、也能回看 |
| 保留「上一句」在上面 | **删掉** —— v1 里当前句和上一句会同时出现同一段文字，看起来像重复；题目更是会在页眉、当前句、上一句里出现三次 |
| 题目固定置顶 | 页眉只留 `Q编号 · 章名` + 页码，**题目本身作为正文第一页** |
| 朗读形式直接上屏（`T P`、`Mo E`） | **音频念「T P」，字幕显示「TP」** —— 反向折叠只针对我们自己插入的空格，所以是安全的 |

### 断行：按标点分层，不按宽度硬折

表格转出来的答案长这样：

```
策略：TP（张量并行）；切什么：层内的权重矩阵（按列/行切）；解决什么：单层放不下一张卡；代价：…
```

**`；` 是语义边界**（每个「字段：值」是一组）。按宽度硬折会把一组劈到两行：

```
答案：策略：TP（张量并行）；切什么：层内的权重矩阵     ← 差
（按列/行切）；解决什么：单层放不下一张卡；代价：每层
```

所以断行优先级是：

| 优先级 | 断在哪 | 效果 |
|---|---|---|
| 1 | **`；。！？`** | 每个子句独占一行 —— 一个字段一行，看着就是一张对照表 |
| 2 | `，、：` | 子句本身超宽时才在这里断 |
| 3 | 硬切 | 英文长标识符才会走到这一步 |

实际输出：

```
答案：策略：TP（张量并行）；
切什么：层内的权重矩阵（按列/行切）；
解决什么：单层放不下一张卡；
代价：每层两次 all-reduce，通信最频繁。
策略：PP（流水并行）；
切什么：按层切；
```

> **两个必须踩过的坑**：
> ① **宽度得混合计** —— 早先「有中文就只数中文」，
> `这是常见的口误（推理没有反向）推理 DP 的每个副本…` 算出来 31、实际约 35，直接顶出右边界。
> 现在 CJK 记 1、拉丁/数字/半角标点记 0.5。
> ② **`第 N 题。` 的句号在屏幕上要换成空格** —— 否则它会被当成句末标点，孤零零占一行。

分页：优先在空行（段落）断，其次 `；。！？`，最后逗号；**并且保证换行后真的放得下**（放不下就往回退，实在不行二分找边界）。每页时长由 WordBoundary 时间戳决定，约 30–40 秒。

### 几个踩过的坑（都已修，且都验证过）

| 坑 | 现象 | 根因 / 修法 |
|---|---|---|
| **`boundary` 默认不是 WordBoundary** | 一个时间戳都收不到，字幕退化成按字数估算 | `edge_tts.Communicate(..., boundary=...)` 默认 `"SentenceBoundary"`，必须显式传 `"WordBoundary"` |
| **edge-tts 不给标点发边界事件** | 直接把 word 拼起来会得到「第132题TPPPDPEP分别解决什么问题」 | 把每个 word **对齐回原文的字符区间**，行文本一律从原文切片 |
| **libass 不给中文自动换行** ⚠️ | 整段文字**同时溢出左右边界**（左留白里测到 YMAX=230 的白字） | 宽度自己算（CJK=1、拉丁=0.5），断点用 `\N` 写死，ASS 配 `WrapStyle: 2` |
| **ffmpeg 滤镜里的 Windows 路径** | `ass=C:/...` 报 `Invalid argument` | 盘符冒号要转义：`ass='C\:/...'` |
| **SRT 中文乱码** | VLC / Windows 播放器显示乱码 | SRT 用 `utf-8-sig`（带 BOM） |
| **宽度只数中文** | 含英文的行顶出右边界 | CJK 记 1、拉丁/数字记 0.5，混合累加 |
| **`第 N 题。` 独占一行** | 朗读的停顿被当成断句 | 显示形式里把那个句号换成空格 |

### 怎么验证「看不见的东西」

我看不了图、也听不了声，所以版式是靠 **ffmpeg 的 `signalstats` 量像素亮度**验证的：

| 位置 | 期望 | 实测（Q132 / Q262） |
|---|---|---|
| 左留白 `x=0..70` | 只有进度条（蓝，YMAX≈119），**不能有白字** | 119 ✅ |
| 右留白 `x=1210..1280` | 只有页码（灰，YMAX≈138） | 137–140 ✅ |
| 正文区 `y=120..660` | 白字（YMAX≈235–240） | 233–239 ✅ |
| 正文最底部 `y=654..660` | 纯背景（不能压到进度条） | 35 ✅ |

**改版式后照这个方法复测一遍**，比肉眼看更可靠。

### 合并成一个长视频（`--merge-all`）

3 小时以上的视频**没有章节根本没法用**，所以合并时会写入 **MP4 章节标记** ——
每道题一个 chapter，标题形如 `Q132 · TP、PP、DP、EP 分别解决什么问题？`：

```
$ ffprobe -show_chapters interview-all.mp4
0  Q1 · cache line 由哪三部分组成？各自的作用？
1  Q2 · 为什么需要多级缓存？
2  Q3 · 发生 cache miss 后硬件的处理流程？
…
```

- **不重编码**：所有片段分辨率/编码/采样率一致，`ffmpeg -f concat -c copy` 直接拼
- **`+faststart`**：moov 前置，边下边播不卡
- **`chapters.txt`** 另存一份，方便别的工具（B 站分 P、剪辑软件）用
- **PotPlayer / VLC / IINA / 哔哩哔哩**都认这个章节，可以直接在进度条上跳题

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--page-chars` | 270 | 每页最多多少字 |
| `--page-lines` | 10 | 每页最多多少行（上限还会被屏幕高度压） |
| `--probe Q132` | — | 只做一题，先看效果 |
| `--chapter` / `--all` / `--limit` | — | 范围 |
| `--chapter-merge` | — | 每章合成一个长视频（`-c copy`，不重编码） |
| **`--merge-all`** | — | **把全部题拼成一个长视频**，并写入章节标记 |
| `--out-name` | `interview-all.mp4` | `--merge-all` 的输出文件名 |
| `--keep-work` | — | 保留 `.work/` 里的 `.ass` 与 `.mp3`，调版式时用 |

改版式：`build_video.py` 顶部 `PAGE_SIZE`（**现 37px**）/ `MARGIN_LR` / `MARGIN_TOP` / `LINE_H` / `BG`，以及 `ASS_HEAD` 里的颜色。

> **字号和每页行数是联动的**：`每行字数 = (1280 − 2×MARGIN_LR) ÷ PAGE_SIZE`、
> `每页行数 = (720 − MARGIN_TOP − 46) ÷ (PAGE_SIZE × LINE_H)`。
> 37px 时是 **每行 30 字 / 每页 10 行**，正文区 525px，正好塞进 546px 的可用高度。
> **调大字号后一定要重跑溢出检查**（下面的像素亮度法）。

### 体积与耗时

| | 数值 |
|---|---|
| 单个视频 | 约 **1 MB / 分钟**（画面近乎静止，H.264 压得很狠） |
| 全量 254 题 | 约 **200 MB** / 3.3 小时 |
| 编码速度 | 约 **0.1× 实时**（Q262 的 111 秒视频用 14 秒） |
| 全量耗时 | 约 **20–30 分钟**（合并那一步是 `-c copy`，几十秒） |
